5 Configuring a Sales Document Type

Field-by-field walkthrough of Define Sales Document Types [VOV8] and the standard SAP order types built on it.

Core SD Header Control Object

"What kind of document is this, and how should the system behave because of it?"

The sales document type is the single control record that tells SAP whether an entered document is an order, a quotation, a returns request, or something else — and it drives number ranging, pricing procedure determination, output, incompletion, and billing behavior for the entire header. Configured via Define Sales Document Types [VOV8], path: SPRO | Sales and Distribution | Sales | Sales Documents | Sales Document Header.

Always Copy, Never Edit Standard

1
New document type: copy the SAP type that's the closest functional match (e.g. copy TA/OR for a new order type) so item category and schedule line category determination plus copy control rules come with it.
2
Changing an SAP type: never edit it directly — copy it into the customer namespace (e.g. TA → ZTA) and change the copy instead, leaving the SAP standard untouched.
3
Namespace rule: any new key must begin with Y or Z — SAP guarantees it will never overwrite these during an upgrade.
4
Save confirmation: when you click Copy, confirm "Yes" to copy control rules so the source document's control tables replicate automatically for the new type.

Number Ranges

Every document type needs both an internal and an external number range interval assigned, even if only one is actively used.

Internal number range01
System assigns the next available number automatically on save.
External number range02
User enters the number manually (or it's inherited from a legacy system).
Transport gotcha: number range intervals are not automatically transported with the document type. If a duplicate-number error appears after a transport, check/reset the current number counter directly in SE16/SE16N on the number range table in the target system.

VOV8 Field Walkthrough — Standard Order Type TA/OR

Reading the configuration of document type TA (Standard Order) section by section, per SAP's own settings.

Document Category = C

Marks this as a sales order category, distinct from a quotation (B) or contract. Not editable once you're inside a copied type — set at creation.

Blocked

Blank — the type is unblocked and usable. Set to block a type from being used while it's still being configured.

Item / Sub-item Increment

10 / 10 — items number 10, 20, 30... leaving gaps for manually inserted lines; sub-items (BOM components) increment the same way.

Reference Mandatory

Blank for TA — an order does not require a preceding quotation. Quotation/contract types typically leave this blank too; some custom types require reference to an invoice for traceability.

Document Probability

100% for a standard order — the sale is treated as certain. Quotations instead combine an order-probability % from the customer master with the document type's own %.

Read Info Record

Checked — the system reads the customer-material info record (custom material numbers, descriptions, delivery tolerances) if one exists.

Output Application

Assigned for sales (V1) so output determination — order confirmations, EDI, etc. — can trigger. Full detail in output determination (Chapter 9).

Screen Sequence Group

Controls which screens/tabs and in what order the user sees when processing this document type (e.g. group AU for standard orders, AG for quotations).

Incompletion Procedure

11 at header level — determines which fields must be filled before the document is considered complete. See incompletion procedures (Chapter 4).

Transaction Group

Determines which statistics/indices get updated with reference to this document type (sales order, billing document, etc.).

Quotation/Contract Messages = B

Warns the user at order entry if an open quotation or contract already exists for this Sold-to Party and material — nudging them to reference it instead of creating a fresh order.

Document Pricing Procedure

This indicator, combined with the customer master's pricing procedure indicator and the sales area, determines which pricing procedure the order uses — see Configure Pricing.

Also on the header: Status Profile (assigns a user status schema, also settable at item category), Credit Limit Check (blank = no check; see credit management, Chapter 10), Purchase Order Number check, Commitment Date check, Division copy + division-mismatch error check, and Incomplete Messages (blank = warn on save but still allow saving).

Requested Delivery Date & Contract Fields

Lead Time in Days: normally 0 — no artificial padding on the requested delivery date.
Propose Delivery Date: checked, so today's date is proposed by default.
Proposal for Pricing Date: pricing date defaults from the reference document, requested delivery date, or current date.
Contract Profile / Group Reference Procedure / Follow-up Activity Type: only relevant for contract and master-contract document types (Chapter 4).

Restricting a Document Type to Specific Sales Areas [OVAZ]

Menu path: SPRO | Sales and Distribution | Sales | Sales Documents | Sales Document Header | Assign Sales Area To Sales Document Types.

Sales Org 1000 + Dist. Channel 10 + Division 00 ──▶ Allowed Doc Type: ZTA

If a document type is valid across every sales area, leave OVAZ blank for it entirely — no entry needed. Use OVAZ only when a document type must be restricted to specific sales organizations (e.g. a country-specific order type). Don't confuse this reference-sales-area assignment with common distribution channel/division master data sharing — they solve different problems.

Standard Special Sales Document Types

Each of these reuses the same VOV8 field set above — only a handful of settings actually change per type.

Type Process Key VOV8 Settings
AG (QT) Quotation Doc category B; screen sequence group AG; transaction group 2; item category AGN; has a validity period and can be copied forward into an order.
BV Cash Sale Immediate delivery + billing date default to today; delivery and cash invoice created automatically on save; invoice posts to a cash account, not A/R.
SO Rush Order Immediate delivery creation like BV, but billing follows the standard delivery-related flow (invoiced after goods issue, not printed at save).
G2 Credit Memo Request Mandatory reference to originating invoice recommended; automatic billing block for release control; item category G2N; no goods movement.
L2 Debit Memo Request Item category L2N; no goods movement; billing block rarely used since there's no fraud risk in undercharging correction.
RE Returns Doc category D; creates a returns delivery for physical goods receipt; mandatory reference to invoice recommended for traceability; order reason often required via incompletion procedure.

Top Certification & Project Takeaways for Sales Document Type Configuration

Must Know
Copy, don't create from scratch: always copy the closest-matching SAP type so item category, schedule line category, and copy control determination come with it.
Y/Z namespace only: never modify a standard SAP document type directly — copy it into a Z-type so upgrades never overwrite your changes.
Document Pricing Procedure indicator here + the customer master indicator + sales area together determine the pricing procedure used — the single biggest cross-reference to remember.
Number ranges don't transport automatically — a duplicate-number error after a transport means checking the number range table via SE16/SE16N in the target system.
OVAZ is opt-in restriction: a document type with no OVAZ entry is valid for every sales area — only add entries when you need to limit usage.
Special types reuse the same field set: cash sale, rush order, credit/debit memo requests, and returns all differ from a standard order by only a handful of settings, not a different mechanism.
